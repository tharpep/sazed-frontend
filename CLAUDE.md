# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `pnpm dev` — Vite dev server at http://localhost:3000 (web only)
- `pnpm dev:homelab` — same, against the live homelab console: mode `homelab` (`.env.homelab`) sets relative `/api` + `/gw`, and `vite.config.ts` proxies them to `https://sazed.tail77c590.ts.net` (override with `SAZED_LAB_URL`). Needs Tailscale on. No keys locally; Caddy on CT 106 adds them.
- `pnpm tauri dev` — Tauri desktop window (requires Rust toolchain)
- `pnpm build` — TypeScript check + Vite build, then `vite.cards.config.ts` builds `dist/cards/widget.html`
- `pnpm tauri build` — Full desktop build after `pnpm build`

## Architecture

**Stack:** React 19 + TypeScript, Vite 7, Tauri v2, Zustand, Tailwind v4 + shadcn/ui (Base UI primitives, owned as source under `src/components/ui/`) + Motion for chat/journal/layout. Settings, Finance and the older widgets still use CSS Modules against a compatibility token layer (see Conventions). Package manager: pnpm.

The app talks to the **Sazed** backend (agent API). Base URL and API key come from env: `VITE_SAZED_URL` (default `http://localhost:8000`) and `VITE_API_KEY` (optional). All requests go through `src/api/client.ts` (`apiFetch`), which sends `X-Sazed-Shape: 2` so dispatch and profile routes answer in the post-035 shape.

**Layout (`App.tsx` + `components/shell/`):** the console is phone first and has one hub shell. `AppShell` wraps `HubFrame` in an error boundary. Below 640px `HubFrame` draws `PhoneHeader`, the page, the docked composer and `HubBottomBar`; from 640px it draws `HubRail`, `HubTitleRow` and the page panel (DESIGN.md, Layout and shell). `WindowBar` adds window controls and a drag area in the Tauri window only. `App.tsx` renders the active view into `HubContent` from `navStore` through the hub registry (not routes — see below), and docks the composer on Chat and on Home on phones. `main.tsx` separately mounts a `BrowserRouter` with two real routes: `/` (the app, i.e. `App.tsx`) and `/display` (`DisplayPage`, the always-on display; see `src/features/display/` below).

**View switching is store state, not routed.** The console uses six hubs: Home, Chat (Conversations, Conversation), Work (Projects, Board, Plans), Agents (Runs, Automations, Profiles, MCP servers), System (Homelab, Activity, Usage, Integrations) and Library (Notes, Knowledge, Journal).
- `src/nav/hubViews.ts` lists the hubs and Apps with their views (ids and labels).
- `src/nav/hubs.ts` points each view at the page that renders it today.
- `src/store/navStore.ts` holds the active hub, each hub's view and each view's filter (`sub`) in localStorage, the open item (`open`) and reader (`read`) per view, scroll positions, and recent items (sessionStorage). `openItem(ref)` switches to the item's hub and view (`ITEM_PLACE`) and opens it there, so links, the palette and Recent open items the same way. A fresh load opens on Home.
- `src/nav/history.ts` mirrors navStore into browser history (`history.state`, never the URL), so Back and Forward and the phone's back gesture move through hubs, views and opened items. Opening pushes an entry; an in-app close that lands on the entry beneath goes back instead; a reload restores the place.
- `src/nav/deepLinks.ts` parses `?page=` links, including the `?page=<hub>`, `?page=<hub>.<view>` and `?page=<hub>.<view>.<picker choice>` aliases, and `?open=<kind>:<id>` (backlog, job, automation, dispatch, service), the form Pushover buttons use; `pnpm test` guards it. `src/nav/openLink.ts` opens an `?open=` item only after its GET confirms the id, so the console lands on Home first, Back returns there, and an unknown id stays on Home.
- `uiStore` holds transient UI state: private apps revealed and the Settings dialog's open state. Navigation state belongs in `navStore`. Apps is a seventh destination with no views. Settings shows as a dialog over the hub shell.

`FinancePage` still exists but no hub or view renders it; Finance was excluded from navigation by product decision, not deleted.

**Theming:** `components/theme/ThemeProvider.tsx` — light/dark/system, persisted to `localStorage` (`sazed-theme` key), toggles the `.dark` class on `<html>`. `ThemeToggle` lives in Settings, and the command palette offers the same three choices.

- `src/features/home/` — `HomePage`, the Home hub and the command center for agents. The greeting (tapping the name toggles private apps, `uiStore.privateRevealed`, in memory only and cleared whenever the console is backgrounded) sits over a counts line. The left column has Needs you, Working now and a done-in-the-last-day line. Needs you shows needs_me cards with an inline answer box for questions. Working now shows running and queued jobs as cards with their last two steps, tool count and time against the timeout. A card sheet shows Now and the agents for a card with a live session (`SessionNow`), taking the session from the command poll over the card's board snapshot. The nav badge counts session questions too. In dev, `localStorage["sazed-mock-sessions"] = "1"` serves `src/mock/sessions.ts`. The right column has Projects in flight (step bars), recent Activity and a one-line homelab summary. Data comes from Sazed's `GET /board/command`, polled every 4 s while visible, plus projects, activity and homelab every 30 s. Buttons come from each card's `actions` (`CardActions`), run through `POST /board/{id}/actions/{action}`. Clicking a job opens `JobSheet`, which now shows a step timeline (the job's `timeline`) and Steer for running jobs. An ask field (docked on phones, inline from 640px) starts a new chat and opens it in Chat.

- `src/features/display/` — `DisplayPage`, the always-on `/display` route: the Pixel 4 XL kiosk (landscape), and later other kiosks, a homepage or a desktop widget. On direction D, with the Display exceptions in DESIGN.md.
  - Laid out by its own box (`modeFor`, a ResizeObserver), not the device: landscape (clock and chips left, the card right), portrait, wide (all four cards at once), widget (clock and two Next up rows) and tiny.
  - Distance tiers on touch screens in landscape or portrait (`usePresence`): near is the full layout and lasts 2 minutes after a touch; far is a big clock and the top three Next up lines, entered when the voice phase leaves idle or near runs out; idle is a dim clock after 10 minutes with neither. Presence is touch plus speech the VAD hears (conversation mode); a camera source can call `seen` later. Other boxes always show near.
  - Talking takes over the screen in landscape, portrait and wide: B's ring while listening, then the question and a state line on one side and the answer card on the other, with the ask bar for follow-ups.
  - The card (`Carousel` in `parts.tsx`): Next up, This week, Mail, Homelab, swiped sideways. It doesn't rotate on its own; it rests on Next up and slides back a minute after the last touch. `items.ts` builds the rows: whatever waits on Pryce (jobs, approvals, services down) first, then events, tasks due and the next automation.
  - `useDisplayFeed` polls each source on its own interval and keeps the last good value; no model calls on load. Weather is Open-Meteo at the browser's position, cached in localStorage.
  - `useVoice`: speech in (Silero VAD in the browser, server Whisper for the text, Web Speech recognition only as a fallback when the VAD can't start), the streamed answer in the talking face, speech out sentence by sentence, conversation mode. Stop (tap, Escape) aborts the stream and the audio; speaking over Sazed (Voice interrupts, on by default) does the same and starts the next turn; a mic tap with no speech for 8 s or an empty transcript closes the mic; a session older than 10 minutes starts fresh. Agent widgets in an answer go through `WidgetRenderer`, with `ask` as their send callback.
  - Screen context: every voice turn sends `screen` (at most 12 lines): the visible card's rows (`screenLines` in `items.ts`), or `describeWidget` of the answer's widgets while one shows. Tapping a row marks its line with `* ` and opens the mic for one turn about it.
  - Always-on: screen wake lock, the layout drifts a few pixels a minute, landscape swaps the clock and card sides every hour, and on touch screens a red night face (the clock and the first thing tomorrow) from 22:00 to 07:00 (a tap wakes it for 30 s). At night `useVoice({ quiet })` stops the always-on mic; only a mic tap opens it, for one turn without the wake word. Installing from `/display` uses `public/display.webmanifest` (starts at `/display`, full screen, landscape).

- `src/features/auth/` — `AuthGate`, wraps the whole app in `main.tsx`.
- `src/cards/` — MCP Apps build of the catalog: one self-contained HTML file holding every widget. The gateway fills in the `__WIDGET__` meta tag per `ui://` resource, and the tool's structured result becomes the widget's props. `card.css` maps the host's theme variables onto the widgets' tokens. `card-schemas.json` is each card's props as JSON Schema, generated from the catalog (`UPDATE_CARD_SCHEMAS=1 pnpm test` rewrites it, and `pnpm test` fails while it is stale); api-gateway keeps a copy in `tests/card_schemas.json` for its contract test. The project cards also accept the gateway's `detail="summary"` brief (`projectBrief.ts` rebuilds bars, step counts and the current step from it).
- `src/widgets/` — `CalendarWidget`, `TaskWidget`, `EmailBadge`, `UpcomingWidget`, `WeatherWidget`, `ClockWidget`, `GitHubWidget`, `HomelabWidget`, `JobWidget`, `JobsWidget`, `StorageWidget`, `ContainerWidget`, `InfoCard` (the general card behind the gateway's `show_card` tool; these five share `StatusCard.module.css`), `ConfirmCard` (a sensitive tool waiting for approval; Yes or No sends "yes" or "no" as the next message through `WidgetRenderer`'s `onSend`, and ownership `system` keeps it out of the catalog prompt), `catalog.ts` (one definition per widget: component, Zod props schema, ownership, `describe` for a one-line summary, `live` for widgets that fetch their own data when given no props; compile-time checks tie each schema to its API type and component, and it generates the catalog prompt), `strictSchema.ts` (JSON Schema Claude strict tool use accepts), `WidgetRenderer` (validates props and renders chat's `UIBlock`s, with `FallbackCard` for unknown or invalid ones: one line naming the card, its first failing field and how many fields failed, with the detail in `console.warn`). Import Zod as `import * as z from "zod"`; the named import bundles every locale. Not rendered as a card grid anywhere anymore; `DisplayPage` renders agent widgets in voice answers through `WidgetRenderer`.
- `src-tauri/` — Tauri shell. Window 900×620, min 600×480, `decorations: false`, so `WindowBar` (`src/components/shell/`) draws the window controls and the drag area.

## Conventions

- Visual work follows `DESIGN.md` (direction D: tokens, type scale, shell, components). Start from the approved mockup and say how when you improve on it.
- Before writing a component, look in this order: `src/components/system/`, `src/components/ui/`, the official shadcn registry, the three registries in `components.json`, and only then build it by hand.
- Mock up a new page in `src/dev/mocks/` on the real components with made-up data. The approved mock becomes the page by swapping the made-up data for API calls. A standalone HTML mockup is for work where the visual language itself is in question.
- Chat, journal, and the navigation shell are Tailwind utility classes + shadcn/ui primitives, following the OKLCH token system and Named Rules in `DESIGN.md` (read it before touching visual code in these areas) and the brand/product guidance in `PRODUCT.md`. No CSS Modules in these three areas.
- Settings, Finance and the older widgets remain CSS Modules, styled through `legacy-compat.css`'s token aliases. If you're touching one of these and want it on the new system, that's a real (unscoped) redesign task — flag it rather than half-converting.
- Markdown rendering is enabled in chat message bodies (`react-markdown` + `remark-gfm` + `rehype-highlight`, same stack the journal editor's read view already used).
- Phone first: lay a page out for a 390px phone, then widen it from 640px (`sm`). Tap targets on phones are at least 44px, often `min-h-11 sm:min-h-0`. `useIsMobile` is the same 640px breakpoint.
- `DESIGN.md` and `PRODUCT.md` are the design reference for chat/journal/shell work, replacing the old `ui_reference.html` (removed).
- View switching is `navStore` state, not `react-router` routes — see Architecture above. Only `/` and `/display` are real routes.
