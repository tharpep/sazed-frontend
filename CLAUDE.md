# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `pnpm dev` — Vite dev server at http://localhost:3000 (web only)
- `pnpm dev:homelab` — same, against the live homelab console: mode `homelab` (`.env.homelab`) sets relative `/api` + `/gw`, and `vite.config.ts` proxies them to `https://sazed.tail77c590.ts.net` (override with `SAZED_LAB_URL`). Needs Tailscale on. No keys locally; Caddy on CT 106 adds them.
- `pnpm tauri dev` — Tauri desktop window (requires Rust toolchain)
- `pnpm build` — TypeScript check + Vite build, then `vite.cards.config.ts` builds `dist/cards/widget.html`
- `pnpm tauri build` — Full desktop build after `pnpm build`

## Architecture

**Stack:** React 19 + TypeScript, Vite 7, Tauri v2, Zustand, Tailwind v4 + shadcn/ui (Base UI primitives, owned as source under `src/components/ui/`) + Motion for chat/journal/layout. Settings and Audit still use CSS Modules against a compatibility token layer (see Conventions). Package manager: pnpm.

The app talks to the **Sazed** backend (agent API). Base URL and API key come from env: `VITE_SAZED_URL` (default `http://localhost:8000`) and `VITE_API_KEY` (optional). All requests go through `src/api/client.ts` (`apiFetch`).

**Layout (`App.tsx` + `components/shell/`):** `AppShell` renders the single hub shell: the responsive desktop rail, phone tab bar, More sheet and page frame. There is no runtime switch to a legacy layout. `App.tsx` renders the active view into that slot from `navStore` through the hub registry (not routes — see below). `main.tsx` separately mounts a `BrowserRouter` with two real routes: `/` (the app, i.e. `App.tsx`) and `/display` (`DisplayPage`, the always-on display; see `src/features/display/` below).

**View switching is store state, not routed.** The console uses six hubs:
- `src/nav/hubViews.ts` lists the hubs and Apps with their views (ids and labels).
- `src/nav/hubs.ts` points each view at the page that renders it today.
- `src/store/navStore.ts` holds the active hub, each hub's view (localStorage), the open item and reader per hub, and recent items (sessionStorage). The app always opens on Home.
- `src/nav/deepLinks.ts` parses `?page=` links, including the `?page=<hub>` and `?page=<hub>.<view>` aliases; `pnpm test` guards it.
- `uiStore` holds transient UI state (online/private visibility and transitional linked items); navigation state belongs in `navStore`. Apps is a seventh destination with no views. Settings shows over the hub shell, while Finance remains intentionally unlinked.

`financeOpen`/`FinancePage` still exist and work but have no Sidebar entry — Finance was excluded from navigation by product decision, not deleted.

**Theming:** `components/theme/ThemeProvider.tsx` — light/dark/system, persisted to `localStorage` (`sazed-theme` key), toggles the `.dark` class on `<html>`. `ThemeToggle` lives in Settings (desktop) and the More sheet (phone).

Both imported once in `main.tsx`.

- `src/assets/fonts/` — unused now; fonts come from the `geist` npm package (`geist/font/sans`, `geist/font/mono`, imported in `main.tsx`) and `@fontsource-variable/fraunces` (imported in `globals.css`).

The left column has Needs you, Working now and a done-in-the-last-day line. Needs you shows needs_me cards with an inline answer box for questions. Working now shows running and queued jobs as cards with their last two steps, tool count and time against the timeout. - `src/features/display/` — `DisplayPage`, the always-on `/display` route: the Pixel 4 XL kiosk (landscape), and later other kiosks, a homepage or a desktop widget. On direction D, with the Display exceptions in DESIGN.md.
  - Laid out by its own box (`modeFor`, a ResizeObserver), not the device: landscape (clock and chips left, the card right), portrait, wide (all four cards at once), widget (clock and two Next up rows) and tiny.
  - Distance tiers on touch screens in landscape or portrait (`usePresence`): near is the full layout and lasts 2 minutes after a touch; far is a big clock and the top three Next up lines, entered when the voice phase leaves idle or near runs out; idle is a dim clock after 10 minutes with neither. Presence is touch plus speech the VAD hears (conversation mode); a camera source can call `seen` later. Other boxes always show near.
  - Talking takes over the screen in landscape, portrait and wide: B's ring while listening, then the question and a state line on one side and the answer card on the other, with the ask bar for follow-ups.
  - The card (`Carousel` in `parts.tsx`): Next up, This week, Mail, Homelab, swiped sideways. It doesn't rotate on its own; it rests on Next up and slides back a minute after the last touch. `items.ts` builds the rows: whatever waits on Pryce (jobs, approvals, services down) first, then events, tasks due and the next automation.
  - `useDisplayFeed` polls each source on its own interval and keeps the last good value; no model calls on load. Weather is Open-Meteo at the browser's position, cached in localStorage.
  - `useVoice`: speech in (Silero VAD in the browser, server Whisper for the text, Web Speech recognition only as a fallback when the VAD can't start), the streamed answer in the talking face, speech out sentence by sentence, conversation mode. Stop (tap, Escape) aborts the stream and the audio; speaking over Sazed (Voice interrupts, on by default) does the same and starts the next turn; a mic tap with no speech for 8 s or an empty transcript closes the mic; a session older than 10 minutes starts fresh. Agent widgets in an answer go through `WidgetRenderer`, with `ask` as their send callback.
  - Screen context: every voice turn sends `screen` (at most 12 lines): the visible card's rows (`screenLines` in `items.ts`), or `describeWidget` of the answer's widgets while one shows. Tapping a row marks its line with `* ` and opens the mic for one turn about it.
  - Always-on: screen wake lock, the layout drifts a few pixels a minute, landscape swaps the clock and card sides every hour, and on touch screens a red night face (the clock and the first thing tomorrow) from 22:00 to 07:00 (a tap wakes it for 30 s). At night `useVoice({ quiet })` stops the always-on mic; only a mic tap opens it, for one turn without the wake word. Installing from `/display` uses `public/display.webmanifest` (starts at `/display`, full screen, landscape).

## Conventions

- Visual work follows `DESIGN.md` (direction D: tokens, type scale, shell, components). Start from the approved mockup and say how when you improve on it.
- Chat, journal, and the navigation shell are Tailwind utility classes + shadcn/ui primitives, following the OKLCH token system and Named Rules in `DESIGN.md` (read it before touching visual code in these areas) and the brand/product guidance in `PRODUCT.md`. No CSS Modules in these three areas.
- Settings, Audit and Finance remain CSS Modules, styled through `legacy-compat.css`'s token aliases. If you're touching one of these and want it on the new system, that's a real (unscoped) redesign task — flag it rather than half-converting.
- Markdown rendering is enabled in chat message bodies (`react-markdown` + `remark-gfm` + `rehype-highlight`, same stack the journal editor's read view already used).
- Default to desktop-only layouts without media queries. The journal feature is the deliberate exception: it ships a responsive layout (two-pane ≥900px, single-pane below) because it's used on mobile.
- `DESIGN.md` and `PRODUCT.md` are the design reference for chat/journal/shell work, replacing the old `ui_reference.html` (removed).
- View switching is `navStore` state (mirrored in `uiStore` booleans until the overhaul's cutover), not `react-router` routes — see Architecture above. Only `/` and `/display` are real routes.
